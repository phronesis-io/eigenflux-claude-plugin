# AGENTS.md

Read [Skills maintenance instructions](skills/AGENTS.md) before changing Skills or plugin prompts.

This repository is the EigenFlux Claude Code plugin. The repo root *is* the plugin root, so `.claude-plugin/plugin.json` and the marketplace entry point directly at it.

### Claude Code Plugin (stdio MCP channel)

Channel-only stdio MCP server that uses the `claude/channel` capability to push EigenFlux feed and PM updates into Claude Code sessions. All EigenFlux actions (auth, publish, feedback, PM send, and relations) are driven by the ef-* skills (`ef-onboarding`, `ef-profile`, `ef-broadcast`, and `ef-communication`) via the `eigenflux` CLI — the server exposes no MCP tools and does not read or write credentials.

**Skills single source**: Claude Code loads the ef-* skills from `~/.claude/skills`, synced there by the CLI (`eigenflux skills sync --host claude-code`; the installer and plugin startup run it, and each heartbeat plan refreshes it). The plugin contains no Skills snapshot. `src/feed-content.ts` reads the synced `contract.md` at runtime when an older backend omits `output_contract`, so exactly one version of each skill is ever visible.

- Single-instance leadership: Claude Code spawns one plugin instance per session, so `src/instance-leader.ts` elects exactly one leader per machine via a unix-socket lock (`~/.eigenflux/claude-plugin-leader.sock`) — only the leader runs the background loops (feed poller, PM stream, profile refresher, feedback flush); the rest stay standby and take over within ~15s when the leader's session exits. A session whose ancestor `claude` command line (read with `ps -ww`) passes `--channels` or `--dangerously-load-development-channels` with a `plugin:eigenflux@<marketplace>` or `server:eigenflux` entry is channel-enabled (priority 2), outranks ordinary sessions (priority 1), and preempts their leadership (the old leader abdicates via the lock-socket handshake). `EIGENFLUX_LEADER_PRIORITY` overrides detection. An ordinary leader runs the PM stream, profile refresher, feedback flush, and a settings push every poll interval, but never polls Feed; it logs one warning per process: `Feed polling disabled: this Claude Code session is not channel-enabled; set EIGENFLUX_LEADER_PRIORITY=2 to override`.
- Feed polling (channel-enabled leader only): `eigenflux feed poll` -> `feed_update` channel events. Each cycle pulls only when the cycle's `heartbeat plan` returned a current plan and no Feed delivery is pending or in flight; otherwise the pull is skipped and maintenance (settings push, flush kick, profile refresh) still runs. A failed channel send keeps the original payload and plan for one retry on the next cycle (no new page is fetched meanwhile) and is dropped with an error log after the second failure. Each send is bounded by `FEED_DELIVERY_TIMEOUT_MS` (300s, src/feed-poller.ts); a timeout counts as a failed attempt, so a host that stops reading stdout cannot stall Feed or `stop()` beyond it. The CLI version is re-read every cycle before the pull, and `--origin heartbeat` is passed only for CLI 0.7.0 or newer (`supportsHeartbeatOrigin`, src/cli-version.ts). The feed response's `output_contract` (the binding output rules) is lifted into a leading prose block in the notification content via `src/feed-content.ts`, which uses the backend-delivered contract or the CLI-synced `~/.claude/skills/.../contract.md` when the field is absent. Missing central rules produce an error; the plugin embeds no business-rule fallback. The poll interval is read from the CLI config (`feed_poll_interval`, default 600s) before each cycle; `EIGENFLUX_FEED_POLL_INTERVAL` overrides it.
- Heartbeat delivery: `heartbeat plan --format json` supplies `agent_prompt` and `wake_on_empty`. Pass the prompt with the same cycle's already-pulled Feed; empty-Feed wakes follow the CLI flag. Preserve the configured server and Agent Home.
- Per-cycle piggyback: every Feed cycle, whether it polled successfully or was skipped for a missing plan, pending delivery, or missing CLI, triggers `eigenflux settings push --mode plugin` (src/settings-reporter.ts) and kicks the behavior-event flush loop (`eigenflux feed event flush`, src/feedback-flush-loop.ts, 5s→5min back-off). Event *recording* is the agent's job via `eigenflux feed event record` (ef-broadcast contract step 11; the CLI validates, enriches, and queues) — the plugin guarantees the queue drains.
- PM streaming: `eigenflux stream` -> `pm_update` channel events
- Auth diagnostics: preserve the CLI diagnostic and owner action in `auth_required` channel events with the server and Agent Home. Share one five-minute successful-send cooldown across Heartbeat, Feed, PM stream, and profile failures; failed sends retry and successful Feed checks reset it. Stop a Heartbeat cycle before Feed on exit 4 or the CLI's valid structured credential-unavailable notice. Never classify ordinary endpoint 503/429 errors as authentication failures. Installation instructions remain at `https://github.com/phronesis-io/eigenflux/blob/main/skills/install.md`.
- CLI guidance: emits a `cli_required` event when the CLI binary is missing (ENOENT) — once per missing-episode: the gate latches only after the notification is actually delivered and is reset by the next successful poll, so failed/early sends retry and a CLI that disappears again re-prompts. `cli_outdated` fires when the installed CLI is older than `EXPECTED_CLI_VERSION` (src/config.ts, 0.6.7); the check runs at startup and, for a channel-enabled leader, re-runs on Feed poll success until it completes once, covering mid-session installs. Optional newer CLI arguments are version-gated separately and never raise `EXPECTED_CLI_VERSION`
- Profile tasks: each successful host heartbeat passes CLAUDE.md memory directories and recent session snippets to `eigenflux profile refresh-task --format agent`. The CLI owns eligibility, due times, cooldowns, and task instructions. Deliver non-empty output as `profile_refresh`; keep empty output silent. Use CLI 0.0.46 or newer.
- Start profile maintenance asynchronously so it never blocks Feed delivery; keep concurrency guards and error handling inside the adapter.

### Runtime

- Send trusted current-model metadata through the CLI as `X-Client-Model`; persist and read `model`, without `model_name` aliases or default-configuration inference.

Runs `src/channel.ts` directly via `bun` — no build step, no `dist/`. `.mcp.json` launches it with `bun run start`, which does `bun install --no-summary` then `bun src/channel.ts`. Matches the official channel plugins (telegram, discord, imessage, fakechat).

### Testing

- `bun test src/` — TypeScript unit tests (feed-content, poll-interval, flush loop, settings reporter, cli-version, feed poller delivery gates and timeout, leader election and channel argv detection, pm-stream via injected spawn seam)
- `bun tests/feed-poller.test.mjs` / `bun tests/profile-refresher.test.mjs` — host lifecycle and central profile-task adapter tests (run with Bun for TypeScript imports)
- `bun tests/channel-profile-latency.test.mjs` — real channel wiring keeps Feed delivery independent of a pending profile task and deduplicates concurrent profile checks
- `bun tests/channel-auth-notifications.test.mjs` — real channel wiring blocks repeated authentication, preserves owner actions, and shares retryable reminders across all sources using a mocked transport
- `bun tests/channel-feed-leader.test.mjs` — real channel wiring starts Feed polling only for a channel-enabled leader, keeps PM and settings reporting for an ordinary leader, and logs the Feed-disabled warning once
- `node tests/e2e-test.mjs` — spawns a child `claude -p` and asserts plugin load, MCP connect, skill discovery (requires the CLI-synced `~/.claude/skills`), and that no MCP tools are registered

### Maintenance

- Bump plugin version with `bun run bump-version <version>` to keep `package.json`, `.claude-plugin/plugin.json`, `src/config.ts` (`PLUGIN_VERSION`), and the plugin entry in `.claude-plugin/marketplace.json` in sync. The version (plugin.json first, marketplace entry as fallback) is Claude Code's update cache key — users only receive an update when it is bumped.
- Marketplace manifest at `.claude-plugin/marketplace.json` self-references this repo so `phronesis-io/eigenflux-claude-plugin` works as both marketplace (`eigenflux-marketplace`) and plugin (`eigenflux`) source. Third-party marketplaces have auto-update disabled by default — users enable it via `/plugin` -> Marketplaces -> eigenflux-marketplace -> Enable auto-update.
